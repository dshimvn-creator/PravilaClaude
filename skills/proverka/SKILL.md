# Проверка перед показом

Скилл выполняет то, что заказчик потребовал зафиксировать: **не показывать
результат, пока сам не проверил, не нашёл ошибки и не исправил их.**

Вызывать в трёх случаях:

1. Перед тем как сказать «готово».
2. Когда заказчик усомнился в цифре или результате.
3. После связного куска работы, до отчёта.

---

## Шаг 1. Источники

- [ ] Список того, что заказчик прислал, сверен с тем, что реально обработано.
      Не по памяти — командой, по папке с исходниками.
- [ ] Нет файлов, которые лежат и не открыты. Если есть — назвать их вслух.
- [ ] Для каждого утверждения о числе: из какого источника оно взято и все ли
      источники по этому объекту открыты.

**Формулировка:** «в разобранном источнике N», а не «у фабрики N».

## Шаг 2. Свежесть

- [ ] Каждый производный файл новее своих исходников.
- [ ] Собранный результат новее данных, из которых собран.
- [ ] Нет двух живых файлов одного назначения в разных форматах.

## Шаг 3. Полнота извлечения

- [ ] Сколько единиц данных видно в источнике против того, сколько доехало
      до результата. Расхождение больше 10% — ошибка, а не результат.
- [ ] Знаменатель считается теми же правилами, что и числитель. Иначе метрика
      врёт в обе стороны.
- [ ] Потери названы поимённо, а не общим процентом.

## Шаг 4. Дубли и противоречия

- [ ] Одинаковые названия.
- [ ] Одна картинка у нескольких записей.
- [ ] Одна запись под разными именами.
- [ ] Противоречивые характеристики у одного объекта.

## Шаг 5. Правки не сломали соседей

- [ ] Исправленное действительно исправилось.
- [ ] Не появилось нового.
- [ ] Проверено то, что зависело от изменённого, а не только сама правка.
- [ ] Код не скопирован из соседнего файла вместе с его багами.

## Шаг 6. Если результат визуальный

- [ ] Битые ссылки и картинки.
- [ ] Мобильная ширина: горизонтальный скролл, выход за экран.
- [ ] Зоны нажатия не меньше 44×44 px.
- [ ] Контраст текста: 4.5 для обычного, 3.0 для крупного.
- [ ] Пустые блоки, перекрытия, элементы нулевого размера.
- [ ] Анимация не оставляет контент невидимым, если её таймлайн заморожен.

Измерять по DOM, а не скриншотами, если панель браузера скрыта: там видно
только первый экран, а переходы стоят на нуле.

## Шаг 7. Требования заказчика

Пройти исходную задачу пункт за пунктом:

- [ ] Выполнено?
- [ ] Выполнено полностью?
- [ ] Выполнено правильно?
- [ ] Не создало ли проблем в другом месте?

## Шаг 8. Взгляд со стороны

Посмотреть на работу так, будто её сделал кто-то другой:
«нашёл бы я здесь ошибки, если бы это делал не я».

Особенно искать то, что легко пропустить при создании: молчаливые фильтры,
допущения о состоянии файлов, цифры без знаменателя.

---

## Если что-то найдено

**Сначала исправить, потом рассказать.** Не сообщать об ошибке до её
устранения. После исправления — вернуться к шагу 5.

## Формат отчёта

    ### Что сделано
    ### Что проверено
    ### Что исправлено после проверки
    ### Что осталось нерешённым

Без пересказа внутреннего процесса. Если хоть один пункт не сходится —
результат не показывается, сначала исправляется.

## В проектах с автоматической проверкой

Если в папке проекта есть `verify.py` или подобный скрипт — запустить его
до и после работы и сравнить. Правка, не увеличившая полноту, не считается
сделанной.
